
# Task/Callback 선택

뒤끝은 총 2가지의 함수 방식을 지원합니다.  
* Task 방식(async/await)
* Callback 방식

각각의 함수 방식에는 장단점이 있으며, 상황에 따라 필요한 것을 사용하시면 됩니다.  
일반적으로 흐름제어가 수월한 Task 방식을 추천합니다.  

## Task 방식
요청 시점에서 await를 통해 결과를 받을 때까지 대기가 가능한 함수입니다.    
함수를 호출하면 리턴 값이 반환될 때까지 비동기 방식으로 동작하므로 메인 스레드가 멈추지 않습니다.  
await를 통해 각 함수를 대기하면서 순차처리가 가능하므로 흐름제어가 수월합니다.  
~Async로 끝나는 함수 형태를 가지고 있습니다.  

### 사용되는 상황
**대부분의 상황**에서 함수 호출 시 사용이 추천됩니다.  
**결과를 받을 때까지 확실하게 대기** 해야 하는 경우에 추천됩니다.  
**함수를 순서에 맞게 처리** 해야 하는 경우에 추천됩니다.  

### Example
```js
//유저 정보 불러오기
var reqResult = await BackndAuth.Instance.GetUserInfoAsync();
// 이후의 행동
```

## Callback 방식
Task처럼 비동기로 동작하지만 결과값을 기다리지 않는 함수입니다.  
Callback 함수의 경우 함수를 호출한 쓰레드에서 해당 호출에 대한 결과를 기다리지 않고 바로 다음 작업을 수행할 수 있습니다.  
다른 외부 함수의 콜백내에서 실행해야 하는 경우나 호출만 하고 결과를 받는 시점을 고려하지 않아도 되는 경우에 사용합니다.  
결과값을 기다리지 않으므로 결과 처리는 Callback 안에서 이루어져야 하기 때문에 순차적인 처리는 제어가 어렵고 가독성이 좋지 않습니다.  
* 서버로 보내는 요청이 OS 스케줄러에 따라 대기하고 있다가, 대기하고 있던 요청들이 한 번에 서버로 전송되는 경우 요청 시간이 비정상적으로 길어질 수 있습니다.  
* 현재 클라이언트에서 사용 중인 비동기 IO 스레드의 개수보다 많은 수의 비동기 요청을 한 번에 호출할 경우 새로 IO 스레드를 생성하는 과정에서 요청 시간이 비정상적으로 길어질 수 있습니다.  
* 현재 시점에 요청 8개 이하 호출하는 것이 권장  
* 함수가 순차적으로 호출될 필요가 없을 때  
* 게임 종료 시점에 현재 데이터를 종료할 때  

### Example
```js
//유저 정보 불러오기
BackndAuth.Instance.GetUserInfo(callback =>
{
// 이후의 행동
});
```
