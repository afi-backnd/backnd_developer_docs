# 유저 관리 - 멀티 캐릭터

멀티 캐릭터는 하나의 **계정**으로 여러 **유저**를 플레이할 수 있는 기능입니다.  
이 페이지는 **멀티 캐릭터 프로젝트의 차이점** 위주로 구성되어 있습니다. 공통 동작은 [검색/생성/삭제](/guide/console-guide/backnd-base/users/basic), [유저 정보 조회](/guide/console-guide/backnd-base/users/search), [유저 복사](/guide/console-guide/backnd-base/users/usercopy)를 참고해 주세요.

## 계정과 유저 정의

멀티 캐릭터 프로젝트에서는 인증을 담당하는 **계정**과 실제 플레이를 담당하는 **유저**로 정보가 구분됩니다.

![싱글 캐릭터 환경과 멀티 캐릭터 환경 비교](/img/docs/guide/base/multi-character/single-vs-multi-character.png)

- **유저는 직접 로그인하지 않습니다.** 계정으로 로그인한 뒤 플레이할 유저를 선택합니다.
- 그룹, 길드, 친구, 우편, 리더보드, 게임 정보 등 **플레이 데이터는 모두 유저 단위**로 관리됩니다.
- 로그인, 탈퇴, 차단 등 **인증 · 계정 성격의 처리는 계정 단위**로 동작합니다.

:::info 용어
콘솔에서는 플레이 단위를 계속 **유저**로 표기합니다. SDK 문서의 **캐릭터**와 같은 대상입니다.
:::

## 멀티 캐릭터 활성화

**유저 환경설정** 메뉴에서 멀티 캐릭터를 활성화하며, 운영 중인 프로젝트에서도 활성화할 수 있습니다.

1. **멀티캐릭터 활성화** 버튼을 클릭하면 확인 모달이 표시됩니다.
   - "멀티캐릭터 기능을 활성화 하시겠습니까? ※ 활성화 후에는 이전 환경으로 되돌릴 수 없습니다."
2. 확인 후 처리가 완료되면 상태 배지가 **비활성화 → 활성화**로 변경됩니다.
3. 활성화 후 유저 메뉴에 **유저 탭 / 계정 탭**이 추가됩니다.
   - **탭 순서 설정**에서 두 탭의 노출 순서를 변경할 수 있습니다. 멀티 캐릭터 비활성 상태에서는 설정할 수 없습니다.

![유저 환경설정 - 멀티 캐릭터 활성화](/img/docs/guide/base/multi-character/multi-character01.png)

:::caution
- 멀티 캐릭터로 활성화한 프로젝트는 기존 환경으로 되돌릴 수 없습니다.
- 활성화 후 기존 유저를 계정으로 승격 처리해야 합니다. ([Elevate](/sdk-docs/backend/base/multi-character/elevate))
- 계정으로 승격한 후에는 이전으로 되돌릴 수 없습니다.
:::

## 운영 중이던 프로젝트 전환 시

싱글 캐릭터로 운영하던 프로젝트는 활성화 이후 기존 유저를 계정으로 승격해야 여러 유저를 사용할 수 있습니다. 멀티 캐릭터를 활성화하는 것만으로는 기존 유저가 계정이 되지 않습니다.

### 승격 시 처리 내용

기존 유저를 계정으로 승격하면 인증 정보만 계정으로 분리되고, 플레이 데이터는 그대로 남습니다.

1. 기존 유저의 인증 정보를 승계한 **계정이 새로 생성**됩니다.
2. 기존 유저는 그 계정에 속한 **유저로 전환**됩니다.
3. 그룹, 길드, 우편, 랭킹, 게임 정보 등 **플레이 데이터는 그대로 유지**됩니다. 별도 이관 작업은 필요하지 않습니다.
4. 승격 이후부터 해당 계정에 유저를 추가로 생성할 수 있습니다.

승격 전까지 기존 유저는 로그인과 플레이를 함께 수행하는 상태로 남아 있으며, 이 상태에서는 유저를 추가로 만들 수 없습니다.  
(한 프로젝트 안에 승격한 유저와 승격하지 않은 유저가 함께 존재할 수 있습니다.)

### 승격 방법

- 승격은 **SDK에서 처리할 수 있습니다.**
- 게임 클라이언트에서 로그인한 뒤, 응답으로 승격이 필요한 상태인지 확인하고 계정 전환 함수를 호출합니다.
- 자세한 방법은 [Elevate](/sdk-docs/backend/base/multi-character/elevate)를 참고해 주세요.

## 유저 목록

계정 소속 여부와 관계없이 **모든 유저**를 조회합니다. 유저 단위 정보와 소속 계정 정보를 함께 출력합니다.

![유저 목록 화면](/img/docs/guide/base/multi-character/multi-character02.png)

- 유저 UUID: 유저의 고유 식별자. 계정 UUID와 별개의 값
- 계정 ID: 소속 계정의 ID (승격 전 유저는 '-'로 표기됨)
- 계정 상태: 소속 계정의 상태
- 생성일: 유저가 생성된 일시
- 최근 접속일: 유저의 최근 접속 일시
- 누적 결제액: 해당 유저의 결제액

## 계정 목록

**계정**만 조회하며, 계정 정보와 소속 유저의 합산 값을 함께 출력합니다.

![계정 목록 화면](/img/docs/guide/base/multi-character/multi-character03.png)

- 계정 ID: 계정 로그인 시 인증에 필요한 ID
- 유저 닉네임: 계정에 속한 유저의 닉네임
- 계정 UUID: 계정의 고유 식별자
- 가입일: 계정이 생성된 일시
- 최근 접속일: 계정의 최근 로그인 일시
- 누적 결제액: 계정에 소속된 유저의 결제액 합산

### 계정 삭제

계정을 삭제하면 해당 계정에 속한 **모든 유저가 함께 삭제**됩니다.

## 검색

유저 목록과 계정 목록 모두 기본 검색과 상세 검색을 제공하며, 상세 검색 항목은 두 목록이 동일합니다.

### 기본 검색

검색 기준을 하나 선택해 검색합니다. 선택할 수 있는 기준만 목록에 따라 다릅니다.

| 목록 | 검색 기준 |
| --- | --- |
| 유저 목록 | 닉네임, 유저 UUID, 계정 ID, 계정 UUID |
| 계정 목록 | 계정 ID, 계정 UUID, 유저 닉네임 |

- 유저 목록에서 계정 ID · 계정 UUID로 검색하면 해당 계정에 속한 유저가 조회됩니다.

### 상세 검색

계정 정보와 유저 정보를 조합해 검색합니다.

| 기준 | 항목 |
| --- | --- |
| 계정 정보 | 계정 상태, 국가, 접속 OS, 접속 기기 |
| 유저 정보 | **계정 유무**, 생성일, 최근 접속일, 메모 |

**계정 유무**는 멀티 캐릭터에서 추가된 항목으로, 유저 유형을 구분할 때 사용합니다.

- 계정 없음: 아직 계정으로 승격하지 않은 기존 유저
- 계정 있음: 승격 후 계정에 속한 유저

![상세 검색 영역](/img/docs/guide/base/multi-character/multi-character04.png)

## 유저 · 계정 생성

**생성하기**에서 생성 유형을 먼저 선택하며, 선택한 유형에 따라 입력 항목이 달라집니다.

- 유저를 생성하려면 해당 유저가 소속될 계정 UUID를 입력해야 합니다.
- 계정을 생성하려면 계정 ID와 비밀번호를 입력해야 합니다.

![유저 생성하기 모달](/img/docs/guide/base/multi-character/multi-character05.png)

## 상세 보기

목록을 클릭하면 **계정 정보와 유저 정보를 함께** 확인할 수 있는 상세보기가 열립니다.

![멀티 캐릭터 상세보기 모달](/img/docs/guide/base/multi-character/multi-character06.png)

### 계정 정보

계정 데이터와 소속 유저의 합산 정보를 확인할 수 있습니다.

- **계정 데이터**: 계정 ID, 계정 UUID, 가입 유형, 가입일, 최근 접속 OS, 최근 접속일, 최근 접속 기기, 디바이스 정보, 기타 정보
- **소속 유저 합산**: 누적 결제액, TBC
- **유저 수**: 해당 계정이 보유한 유저 수
- **상태/제재**: 차단과 탈퇴 모두 계정 단위로 처리됨. 계정에 속한 유저는 개별 탈퇴할 수 없으며 탈퇴 목록에도 노출되지 않음

### 유저 정보

드롭다운에서 유저를 선택하면 해당 유저의 정보가 아래 영역에 출력됩니다.

- 닉네임: 필요 시 수정할 수 있음
- 우편 목록, 친구: 클릭하여 상세 목록을 조회할 수 있음
- 국가/언어: 유저 값을 우선 출력하며, 값이 없을 경우 계정 값이 출력됨
- 메모: 유저 단위로 구분

## 유저 접근

접근 허용 및 차단은 **계정 단위**로 처리됩니다.

### 접근 차단

- 멀티 캐릭터 프로젝트의 접근 차단은 **계정 UUID 기준**으로 관리됩니다.
- 계정을 차단하면 해당 계정에 속한 **모든 유저가 함께 차단**됩니다.
- 유저가 여러 개인 계정은 차단 목록에 `닉네임 외 n명`으로 표기되며, 닉네임을 클릭하면 유저 상세보기 모달이 열립니다.

**싱글 캐릭터 프로젝트에서 전환한 경우**

- 승격 전에는 기존 유저가 **유저 UUID 기준**으로 차단 상태를 유지합니다.
- 계정으로 승격하면 **계정 UUID로 자동 변경**되어, 승격 전의 차단이 그대로 이어집니다.

### 접근 허용

- 멀티 캐릭터 프로젝트의 접근 허용은 **계정 UUID 기준**으로 관리됩니다.

**싱글 캐릭터 프로젝트에서 전환한 경우**

- 승격 전에는 기존 유저가 **유저 UUID 기준**으로 접근 허용을 유지합니다.
- 계정으로 승격해도 **자동으로 변경되지 않습니다.** 계속 허용하려면 **계정 UUID로 다시 등록**해야 합니다.

![접근 차단 목록의 닉네임 표기](/img/docs/guide/base/multi-character/multi-character07.png)

유저 접근 관리 메뉴의 전반적인 사용 방법은 [접근 차단](/guide/console-guide/backnd-base/access-user/blocking), [접근 허용](/guide/console-guide/backnd-base/access-user/allow)을 참고해 주세요.

## 유저 복사

원본 유저의 데이터를 다른 유저로 복사합니다. 복사 타입은 두 가지이며, 타입에 따라 **대상 유저**에 입력하는 값이 달라집니다.

### 복사 타입

- **생성하기**: 신규 유저를 생성하여 복사합니다. 대상 유저에는 유저가 소속될 **계정 ID와 비밀번호**를 입력합니다.
    이미 존재하는 계정이고 비밀번호가 일치할 경우, 해당 계정 하위에 유저가 생성되며 데이터가 복사됩니다.
- **기존 유저로 복사하기**: 이미 있는 유저에게 데이터를 복사합니다. 대상 유저에는 **유저 UUID**를 입력합니다.

### 계정 승격 여부에 따른 처리

'기존 유저로 복사하기'는 원본 · 대상 유저의 계정 승격 여부에 따라 결과가 달라집니다.

| 원본 유저 | 대상 유저 | 결과 |
| --- | --- | --- |
| 계정 있음 | 계정 있음 | 유저와 계정 정보가 복사됩니다. |
| 계정 없음 | 계정 있음 | 유저 정보만 복사됩니다. 원본에 복사할 계정 정보가 없으므로 대상의 계정 정보는 그대로 유지됩니다. |
| 계정 있음 | 계정 없음 | 유저와 계정 정보가 복사되며, 계정이 생성됩니다. |
| 계정 없음 | 계정 없음 | 유저 정보만 복사됩니다. |

### 복사 시 유의 사항

- **원본 유저**에는 **유저 UUID만** 입력할 수 있습니다.
- 유저 UUID를 복사하면 **연결된 계정 정보도 함께 복사**됩니다. 계정 데이터만 단독으로 복사할 수 없습니다.
- 다른 프로젝트로 복사하려면 **대상 프로젝트에도 멀티 캐릭터가 활성화**되어 있어야 합니다.
- 그 외 복사 정책은 [유저 복사](/guide/console-guide/backnd-base/users/usercopy)와 동일합니다.

## CSV 다운로드

유저 목록 · 계정 목록에 따라 다운로드 대상이 나뉩니다.

- 유저 데이터에는 **계정 UUID** 필드가 기본 항목으로 포함됩니다.
- 모달 문구도 목록에 따라 "유저 정보 CSV 다운로드" / "계정 정보 CSV 다운로드"로 구분되어 표시됩니다.

## 다른 메뉴에서의 동작

대부분의 메뉴는 기존과 동일하게 유저 단위로 동작하며, 실제 이용자 수를 기준으로 해야 하는 일부 메뉴만 계정 단위로 처리됩니다.

- **대시보드**: 유저 수 관련 지표는 **계정 기준**으로 집계 (계정에 속한 유저는 집계 대상에서 제외)
- **그룹**: 상세보기 그래프에 **계정 기준 집계** 옵션이 추가되어, 동일 계정에 속한 여러 유저를 1명으로 계산 가능
- **푸시**: 한 계정에 유저가 여러 개여도 동일한 디바이스로는 **1회만** 발송. 유저 간 언어 정보가 다를 경우 마지막에 등록된 유저를 기준으로 전송
- **환불 관리**: 제재 시 **계정 기준**으로 차단

## 제한 사항

- 한 계정에 생성할 수 있는 유저는 **최대 20개**입니다.
- 닉네임은 계정 소속 여부와 관계없이 **전체 유저를 대상으로 중복될 수 없습니다.**
- 멀티 캐릭터 활성화와 계정 승격은 되돌릴 수 없습니다.
- 멀티캐릭터 관련 호출은 유저 관리 항목으로 집계되어 청구됩니다. ([베이스 요금](https://backnd.com/ko/pricing/base/))

## SDK 연동

게임에서는 계정으로 로그인한 뒤 캐릭터를 선택해 플레이 세션으로 전환합니다.

| 기능 | 설명 | 문서 |
| --- | --- | --- |
| 계정 회원가입 · 로그인 | 기존 회원가입 · 로그인 함수를 그대로 사용합니다. 로그인 결과로 프로젝트 모드와 유저 유형을 확인할 수 있습니다. | [회원가입과 로그인](/sdk-docs/backend/base/user/signup-and-login) |
| 계정 전환(승격) | 로그인한 기존 유저를 멀티 캐릭터 계정으로 전환합니다. | [Elevate](/sdk-docs/backend/base/multi-character/elevate) |
| 캐릭터 생성 | 계정에 새로운 캐릭터를 생성합니다. | [CreateCharacter](/sdk-docs/backend/base/multi-character/character/create-character) |
| 캐릭터 목록 조회 | 계정에 속한 캐릭터를 조회합니다. 캐릭터 선택 화면 구성에 사용합니다. | [GetCharacterList](/sdk-docs/backend/base/multi-character/character/get-character-list) |
| 캐릭터 선택 | 선택한 캐릭터의 플레이 세션으로 전환합니다. | [SelectCharacter](/sdk-docs/backend/base/multi-character/character/select-character) |
| 캐릭터 삭제 | 선택한 캐릭터를 삭제합니다. 계정은 유지됩니다. | [DeleteCharacter](/sdk-docs/backend/base/multi-character/character/delete-character) |

:::info 계정 세션과 캐릭터 세션
- 계정과 캐릭터의 accessToken은 각각 발급되어 독립적으로 관리됩니다.
- 다른 디바이스에서 같은 계정으로 다시 로그인해도 기존 디바이스의 캐릭터 세션은 유지됩니다. 여러 디바이스에서 서로 다른 캐릭터를 동시에 플레이할 수 있습니다.
- 계정 세션이 종료되면 캐릭터 목록 조회 · 생성 · 선택 등 계정 레벨 기능을 사용할 수 없으며, 계정 재로그인이 필요합니다.
:::

전체 흐름과 예제는 [멀티 캐릭터란](/sdk-docs/backend/base/multi-character/what-is-multi-character), [멀티 캐릭터 예제 게임](/sdk-docs/backend/base/multi-character/unity-example-project)을 참고해 주세요.
