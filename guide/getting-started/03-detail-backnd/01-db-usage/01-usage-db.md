# DB 이용량 가이드
뒤끝 DB는 '읽기', '쓰기' 두 가지 항목으로 구성되어 있습니다.  

## 일반 읽기/쓰기 처리 기준

읽기/쓰기 작업을 수행할 때는 아래 표를 기준으로 읽기 처리량을 산정됩니다.  
단, 사용하는 기능의 API 작동 방식 및 인덱스 사용량에 따라 발생하는 실제 처리량은 상이할 수 있습니다.  

**읽기 작업**  

| 데이터 크기 | 처리량 | 
| :------------ |:-------------|
| 4KB 이하 | 1 |
> **예시**  
10KB를 불러올 때 사용하는 읽기 처리량은 1처리(4KB) + 1처리(4KB) + 1처리(2KB) = 3처리(10KB)입니다.  

**쓰기 작업**  

| 데이터 크기 | 처리량 | 
| :------------ |:-------------|
| 1KB 이하 | 1 |

> **예시 1**  
96KB를 저장, 수정, 삭제할 때 사용하는 **쓰기 처리량은 96**입니다.  

> **예시 2**  
10KB의 데이터를 1KB로 수정할 때 사용하는 쓰기 처리량은 수정 전, 후를 비교하여 큰 데이터를 기준으로 처리량을 계산합니다.  
수정 전 10KB \> 수정 후 1KB, 따라서 사용하는 **쓰기 처리량은 10**입니다.  

> **예시 3**  
3KB의 데이터를 20KB로 수정할 때 사용하는 쓰기 처리량은 수정 전, 후를 비교하여 큰 데이터를 기준으로 처리량을 계산합니다.  
수정 전 3KB < 수정 후 20KB, 따라서 사용하는 **쓰기 처리량은 20**입니다.  

> **예시 4**  
15KB의 데이터를 삭제할 때 쓰기 처리량은 **15**의 쓰기 처리량입니다.  

## 트랜잭션 처리 기준

트랜잭션 작업의 경우 읽기/쓰기 관계없이 최대 4KB의 데이터만 작업을 수행할 수 있습니다.  
트랜잭션 작업을 수행할 때는 아래 표를 기준으로 읽기/쓰기 처리량을 산정합니다.  
1회의 트랜잭션으로 처리되는 최대 10개의 작업의 총합에 따른 처리량이 아닌 각 작업별로 별도의 처리량 계산되어 합산됩니다.

**트랜잭션 읽기 작업**  

| 데이터 크기 | 처리량 | 
| :------------ |:-------------|
| 4KB 이하 | 2 |
> **예시 1**  
1회의 트랜잭션을 통해 1개의 읽기 작업을 하며 3.5KB를 불러올 때 사용하는 읽기 처리량은 2처리입니다.  

> **예시 2**  
1회의 트랜잭션을 통해 2개의 읽기 작업을 하며 각각 3.5KB, 4.5KB를 불러올 때 사용하는 읽기 처리량은 {2처리(3.5kb)} + {2처리(4kb) + 2처리(0.5kb)} = 6처리입니다.  



**트랜잭션 쓰기 작업**  

| 데이터 크기 | 처리량 | 
| :------------ |:-------------|
| 1KB 이하 | 2 |
> **예시 1**  
1회의 트랜잭션을 통해 1개의 쓰기 작업(저장, 수정, 삭제)을 하며 3.5KB를 사용하는 쓰기 처리량은 2처리(1KB) + 2처리(1KB) + 2처리(1KB) + 2처리(0.5KB) = 8처리입니다.  

> **예시 2**  
1회의 트랜잭션을 통해 2개의 쓰기 작업(저장, 수정, 삭제)을 하며 각각 0.5KB 1.5KB를 사용하는 쓰기 처리량은 {2처리(0.5KB)} + {2처리(1KB) + 2처리(0.5KB)} = 6처리입니다.  


## 데이터 타입 / 크기
뒤끝 DB에 데이터를 저장할 때 저장한 데이터 타입에 맞게 저장됩니다.  
뒤끝 DB에 저장되는 모든 데이터는 인덱스와 인증 정보 등이 추가되기 때문에 row 당 약 200바이트가 증가합니다.
